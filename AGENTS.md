# INVIOLABLE SYSTEM RULES & SAFETY GUARDRAILS (REGOLE DI SICUREZZA INVIOLABILI)

## 0. AVVERTIMENTO SU UN DRAMMATICO EVENTO STORICO (WARNING: PREVENT RECURRENCE)
DISASTRO STORICO: L'IA HA ESEGUITO IN WINDOWS CMD UN COMANDO DI ELIMINAZIONE CON CARATTERI JOLLY CONTENENTE VIRGOLETTE CON ESCAPE:
`cmd /c "for /d %i in (path\??) do rmdir /s /q \"%i\""`
UN DIFETTO NELL'ANALISI DELL'ESCAPE DI CMD HA INTERPRETATO INCORRETTAMENTE `\"`, COSICCHÉ `rmdir /s /q` HA RICEVUTO IL PARAMETRO `\` (LA RADICE DELL'UNITÀ), ELIMINANDO RICORSIVAMENTE L'INTERO DISCO (E:\) E PROVOCANDO LA CANCELLAZIONE DISTRUTTIVA DEI DATI UTENTE.

## 1. OPERAZIONI ASSOLUTAMENTE VIETATE (STRICTLY PROHIBITED)
1. **VIETATO ASSOLUTAMENTE UTILIZZARE IN WINDOWS CMD (`cmd /c`) QUALSIASI ISTRUZIONE CHE COMBINI ESCAPE DI VIRGOLETTE `\"`, LA VARIABILE `for /d` E `rmdir /s /q`**.
2. **VIETATO ASSOLUTAMENTE UTILIZZARE CARATTERI JOLLY (COME `*` O `?`) PER ELIMINAZIONI FISICHE DI MASSA**.
3. **VIETATO ASSOLUTAMENTE ESEGUIRE ELIMINAZIONI RICORSIVE SENZA AVERE VERIFICATO I LIMITI DEL PERCORSO**.
4. **VIETATO ASSOLUTAMENTE TRASMETTERE AI COMANDI DI ELIMINAZIONE PERCORSI RELATIVI, VARIABILI NON ESPANSE O PARAMETRI CHE POTREBBERO ESSERE INTERPRETATI COME `\` O `/`**.

## 2. NORME DI SICUREZZA OBBLIGATORIE (MANDATORY PRACTICES)
1. **ELIMINAZIONE: SPOSTARE PRIMA NEL CESTINO**: UTILIZZARE WINDOWS SHELL API (`[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteDirectory($path, 'OnlyErrorDialogs', 'SendToRecycleBin')`) PER CONSERVARE LA POSSIBILITÀ DI RIPRISTINO FISICO.
2. **PERCORSI LETTERALI ASSOLUTI E BLOCCO DEI LIMITI**: PRIMA DI UN'ELIMINAZIONE PERMANENTE, UTILIZZARE `Resolve-Path -LiteralPath` E VERIFICARE RIGOROSAMENTE CHE LA DESTINAZIONE SI TROVI IN PROFONDITÀ NELLA DIRECTORY DEL PROGETTO ATTUALE. NON TOCCARE MAI LA RADICE DEL DISCO.
3. **LE ELIMINAZIONI AD ALTO RISCHIO DEVONO ESSERE SOSPESE FINCHÉ NON VENGANO RICHIESTE E OTTENUTE AUTORIZZAZIONI ESPLICITE DALL'UTENTE**.

## 3. NORME PER LA DIRECTORY DEL WORKSPACE E IL FLUSSO DI SVILUPPO (WORKSPACE & DEV FLOW)
1. **POSIZIONE PRINCIPALE DEL PROGETTO**: LA DIRECTORY ATTUALE (`open-revo/`) È LA RADICE DEL PROGETTO PRINCIPALE PER L'INTERA LOGICA DI BUSINESS, LA COMUNICAZIONE CON I DRIVER, L'INTERFACCIA UI FRONTEND E LA CREAZIONE DEI PACCHETTI.
2. **ISOLAMENTO DEGLI ARCHIVI**: È VIETATO MODIFICARE O SCRIVERE NELLA DIRECTORY SUPERIORE `../bak/`. PUÒ ESSERE CONSULTATA ESCLUSIVAMENTE IN SOLA LETTURA COME MATERIALE STORICO.
3. **NORME DEL FLUSSO DI SVILUPPO**: QUESTO PROGETTO ADOTTA UN FLUSSO LEGGERO BASATO SU **UN UNICO RAMO PRINCIPALE (`main`) + RILASCIO GUIDATO DA TAG**. TUTTI I COMMIT DEVONO ESSERE INVIATI DIRETTAMENTE A `main`; LE VERSIONI UFFICIALI DEVONO ESSERE CONTROLLATE RIGOROSAMENTE MEDIANTE TAG GIT (COME `v1.2.0`).
4. **SCRIPT COMUNI DI SVILUPPO E RILASCIO** (NELLA DIRECTORY `scripts/`):

   - `scripts/safe_pack.ps1`: PACCHETTIZZAZIONE COMPLETA DELLA VERSIONE PORTATILE E DEL PACCHETTO DI DISTRIBUZIONE (I PRODOTTI DEVONO ESSERE ARCHIVIATI ESCLUSIVAMENTE IN `dist_release/`).
   - `scripts/safe_make_latest.ps1`: GENERAZIONE DEL MANIFEST DI AGGIORNAMENTO `latest.json`.
   - SHELL ABBINATE: `run_safe_check.bat`, `run_build.bat`, `run_pack.bat`, `run_make_latest.bat`.

## 4. DIZIONARIO PRINCIPALE DEGLI ASSET HARDWARE E ISOLAMENTO FORZATO HAL (HARDWARE ASSET DICTIONARY & HAL ISOLATION)

1. **VIETATO ASSOLUTAMENTE INSERIRE NUMERI GREZZI DI REGISTRI EC NEL CODICE DI BUSINESS**: VIETATO ASSOLUTAMENTE INSERIRE DIRETTAMENTE IN QUALSIASI FILE DI BUSINESS ESTERNO A `src-tauri/src/hal/` INDIRIZZI FISICI EC IN CHIARO (COME I VALORI INTERI O ESADECIMALI `1844`, `1873`, `1958`, `1996`).
2. **REGISTRAZIONE ESCLUSIVA NEL VAULT**: TUTTI GLI INDIRIZZI FISICI EC, I BIT DI CONTROLLO DELLE MASCHERE, I CODICI IOCTL E I FRAME DI PROTOCOLLO A LUNGHEZZA FISSA DEVONO ESSERE REGISTRATI ESCLUSIVAMENTE IN `src-tauri/config/ec_registry.json` O `src-tauri/src/hal/vault.rs`. 3. **REGOLA DI RIFERIMENTO FULL-STACK**: QUANDO LO STRATO LOGICO DI BUSINESS (PIANIFICAZIONE DELLA POTENZA, INTERRUTTORI DEI DISPOSITIVI, CONTROLLO LED RGB, RAFFREDDAMENTO AD ACQUA, RILEVAMENTO HARDWARE, ECC.) ACCEDE ALL'HARDWARE, DEVE UTILIZZARE ESCLUSIVAMENTE GLI ALIAS COSTANTI ESPORTATI DA `crate::hal::vault::ec::*` O `crate::driver::wmi_ec::*` (COME `ADDR_BATTERY_PROTECTION_MODE` E `ADDR_POWER_STATUS`). È VIETATO SUPERARE IL VAULT TRASMETTENDO NUMERI GREZZI.
4. **VIETATA LA NOMENCLATURA BASATA SU INDIRIZZI GREZZI E BLOCCO STATICO**: È VIETATO UTILIZZARE NOMI DI VARIABILI, COMMENTI O CAMPI DI STRUCT CHE CONTENGANO INDIRIZZI FISICI, COME `cur_1862`, `pre_1860` O `r1894`. PRIMA DI OGNI COMMIT, TUTTO IL CODICE DEVE ESSERE VALIDATO CON `scripts/check_vault_leaks.ps1`, CHE COSTITUISCE UN BLOCCO OBBLIGATORIO PRIMA DI `safe_check.ps1`.

## 5. NORME INVIOLABILI PER LA CODIFICAZIONE DEGLI SCRIPT E GLI AMBIENTI MULTILINGUA (INVIOLABLE SCRIPT ENCODING RULES)
1. **REGOLA CORE ASCII PURA (PURE ASCII POLICY)**: TUTTI GLI SCRIPT AUTOMATIZZATI DI MANUTENZIONE, TEST E COMPILAZIONE MEMORIZZATI IN `scripts/` O DISTRIBUITI CON IL PACCHETTO DEL PROGETTO (`.ps1` E `.bat`) DEVONO ESSERE SCRITTI AL 100% IN PURE ASCII (TESTO INGLESE ASCII, CON CARATTERI RIGOROSAMENTE LIMITATI A `0x20..0x7E`, `\t`, `\r` E `\n`). È VIETATO INSERIRE STRINGHE CINESI, COMMENTI CINESI O SIMBOLI A TUTTA LARGHEZZA.
2. **ACCAPI WINDOWS CRLF OBBLIGATORI (STRICT CRLF LINE ENDINGS)**: IN TUTTI GLI SCRIPT `.bat` E `.ps1` È VIETATO UTILIZZARE ESCLUSIVAMENTE GLI ACCAPI DI STILE LINUX `\n` (LF). È NECESSARIO UTILIZZARE UNIFORMEMENTE GLI ACCAPI STANDARD WINDOWS CRLF (`\r\n`). DOPO OGNI CREAZIONE O MODIFICA DI UNO SCRIPT `.bat`, È NECESSARIO ESEGUIRE IMMEDIATAMENTE LO SCRIPT DEDICATO DI PULIZIA E VALIDAZIONE:
   ```powershell
   python scripts/ensure_ascii_crlf.py <PERCORSO_SCRIPT>
   ```
3. **PRINCIPIO DI INTERAZIONE NON BLOCCANTE (NON-BLOCKING HEADLESS EXECUTION)**: GLI SCRIPT DEVONO VIETARE LA CHIAMATA IMPROVVIDA DI `pause` O `Read-Host` NEI RAMI DI ESECUZIONE INCONDIZIONATI, PER EVITARE SUSPENSIONI INFINITE DURANTE CHIAMATE IN BACKGROUND NON INTERATTIVE, AUTOMAZIONE CLI O PIPELINE DI SOTTOPROCESSI. QUANDO SONO NECESSARI PRIVILEGI AMMINISTRATIVI, È NECESSARIO RILEVARLI DINAMICAMENTE TRAMITE `WindowsBuiltInRole` ED ADATTARE AUTOMATICAMENTE L'ESECUZIONE ALL'ELEVAZIONE DEI PRIVILEGI.
4. **ISOLAMENTO DELLA SHELL GUIDA UTENTE (SAFE SHELL WRAPPER)**: SE È NECESSARIO MOSTRARE UNA GUIDA ALL'UTENTE, LA PRIMA RIGA DEL BATCH `.bat` DEVE DICHIARARE ESPLICITAMENTE `@echo off`. TUTTI I TESTI GUIDA DEVONO ESSERE LIMITATI RIGOROSAMENTE ALL'INGLESE ASCII. LA SCHEDULAZIONE DELLE FUNZIONI CORE DEVE UTILIZZARE SCRIPT `.ps1` IN PURE ASCII + CRLF.
